Creating Clopen Extensions

Recommendations

  • A .clo file should preferably contain only functions and variable definitions at the non-function level.

No:


let x 0 int
update x += 2

for (i 0 int;i != 6; i += 1) {
    log x
}

Yes:


let x 0 int

fn update_n_print(x) {
    update x += 2

    for (i 0 int;i != 6; i += 1) {
        log x
    }
}

Keeping executable code inside functions prevents unexpected behavior when the extension is imported.

Creating Functions

Extensions should expose functionality through functions. This allows other Clopen files to import and use them safely. 


fn hello() {
    log "Hello from extension"
}

Recomended file order

  • Its recomended to put variables you want to be used by the file importing the extension at the beggining of a file and functions right after

File example:


let PI 3.14159265359 float
let e 2.71828182846 float
